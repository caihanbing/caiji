# Project instructions

## User-visible UI changes

For every future addition or modification to the app's user-visible interface, first prepare a concrete design proposal or mockup and receive the user's explicit confirmation. Do not change UI code until that proposal has been approved. This applies to page structure, navigation, layout, colors, typography, iconography, wording, and interaction affordances. Approval covers only the proposal the user reviewed; ask again before implementing a materially different visual design.

## Task delivery

After completing each requested development task, work in the current workspace without creating a new workspace or branch. Build a new versioned release APK, verify its package, version, signature and SHA-256, commit the completed source and documentation changes, and push directly to GitHub `main` without force pushing. Never include release signing keys or passwords in Git.
