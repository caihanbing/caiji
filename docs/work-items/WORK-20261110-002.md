## 工作概述

依据已批准的三状态高保真稿，为分类明细移除逐笔分隔线，并新增与工资收入项明细一致的左滑删除流程。删除确认后经既有 LedgerViewModel 删除账单，并重新加载当前期间、类型和分类的报告；取消或失败时保留明细，删除末条后仍显示分类空状态。发布版本为 0.5.9 / versionCode 24。

## 范围与验收

### REQ-001 — 分类明细删除与报告刷新

- **需求**：分类明细逐笔行不绘制分隔线；行左滑显示既有账单删除按钮，沿用 100dp 宽、48dp 高、12dp 圆角、danger-soft 背景与40%展开阈值。仅一行展开，右滑收起，点击展开行收起，点击收起行仍可编辑。删除需二次确认；取消不删除，确认使用既有 Repository 删除事务。删除成功刷新当前期间/收支类型/分类；失败保留记录并提示；删除末条后保留分类标题并显示空状态。
- **验收标准**：真实仪器用例验证分隔线移除、左右滑、单行互斥、展开后点击收起、取消、确认成功、删除失败/重试、末条空状态、报告及汇总刷新、编辑返回，窄屏与大字体下金额和按钮可见。
- **实现证据**：`FinancialSwipeDeleteContainer` 提供可复用滑动容器；`EntryRow` 保持既有账单首页行为，`FinancialDetailRow` 复用该容器并不再绘制行分隔线；`MainActivity` 通过 `LedgerViewModel.deleteEntry` 删除后重载同一期间、类型、分类报告。
- **验证证据**：API26/API34全量仪器测试各178/178通过；覆盖取消、失败重试、分类切换后的错误清理、重复确认禁用、末条空状态、编辑和月/年汇总刷新。
- **状态**：VERIFIED
- **延期依据**：不适用：未延期。
- **后续工作**：不适用：未延期。

## 决策

### DEC-001 — 分类明细删除和空状态行为

- **状态**：RESOLVED
- **确认路径**：用户批准三状态高保真稿并确认实现计划。
- **决定**：保留分类详情的筛选上下文；删除最后一条仍停留在所选分类并显示其空状态；失败不移除本地行并可重试。
- **原因**：让分类明细支持与工资详情相同的删除入口，同时避免删除后跳出用户正在查看的分类。
- **取舍**：分类空状态只提供返回路径，不新增其他筛选或记录入口。
- **证据**：用户批准设计稿和明确需求。

## 风险

### RSK-001 — 分类明细删除状态与报表快照

- **状态**：MITIGATED
- **确认路径**：以既有 Repository 删除事务和报告请求序号为依据，并用 API26/API34 全量及实际 MainActivity 流程核验。
- **概率**：低
- **影响**：过期报告快照或重复操作可能让已删除记录继续显示或造成误导。
- **缓解措施**：依赖既有删除后的缓存失效；成功回调显式加载同一筛选报告，删除按钮确认期间禁用。
- **验证**：新增长短/失败/取消及真账本删改测试；验证明细、分类排行、月/年金额同步。
