## 工作概述

依据实机截图统一新增工资收入与“记一笔”的录入视觉和键盘交互：两页金额均置于底部数字键盘上方；新增工资须先选有效收入项才展开键盘，编辑记录默认展开；工资字段、扣款和纯收入保留既有语义。按已批准 A–D 高保真稿实现，发布 0.5.12/code27。

## 范围与验收

### REQ-001 — 需求摘要

- **需求**：统一工资新增收入和账单“记一笔”的输入布局；金额显示与应用内键盘共享显隐状态。
- **验收标准**：工资新增未选择项目时无底部金额区/键盘；选择后显示；切换性质清空选择并收起；当前字段金额正确、八项草稿保留；工资和账单编辑初入展开；备注 IME 隐藏键盘金额；分类、金额、税额与保存行为不回归。
- **实现证据**：`AmountDisplay` 位于 `AmountKeypad.kt`；`SalaryEditor` 与 `EntryEditorScreen` 实现输入显隐；`MainActivity` 保存工资键盘状态。
- **验证证据**：JVM 单测、Lint 和 API26/API34 全量仪器测试各 188 项通过；正式签名 APK `caiji-0.5.12-release.apk` 的 package/version/code、zipalign、签名和 SHA-256 通过；API34 模拟器从 0.5.11/code26 覆盖安装到 0.5.12/code27 后 ¥123.45 账单保留。
- **状态**：VERIFIED
- **延期依据**：不适用：未延期。
- **后续工作**：不适用：未延期。

## 决策

### DEC-001 — 按批准稿控制金额区与键盘

- **状态**：RESOLVED
- **确认路径**：用户确认 A–D 高保真设计，并明确编辑页默认展开。
- **决定**：新工资记录选择收入项后显示键盘；编辑工资与账单默认显示；性质切换收起；当前编辑字段金额显示在键盘上沿。
- **原因**：消除用户实机验证发现的工资与账单输入风格及交互差异。
- **取舍**：扣款明细仍在可滚动内容中，底部金额重复显示当前字段值以便输入。
- **证据**：本会话用户批准的设计稿和实施决定。
