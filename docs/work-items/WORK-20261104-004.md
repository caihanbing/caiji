## 决策

### DEC-001 — Android原生XML解析不使用专有feature

- **状态**：RESOLVED
- **确认路径**：实机截图异常 URI 和 Android 14 libcore 实现。
- **决定**：使用严格 UTF-8/16 Reader 解码、DTD/entity声明拦截、namespace-aware DOM 和拒绝外部资源的 EntityResolver，不设置 Xerces feature。
- **原因**：Android 对 disallow-doctype-decl 抛 ParserConfigurationException，JVM Xerces 支持该开关造成旧测试漏报。
- **取舍**：其他编码、DTD 和实体声明工作簿给出另存建议并拒绝读取。
- **证据**：修复前 API34 instrumented RED；API26/API34 修复后原样例通过。

### DEC-002 — 导入错误使用分级可操作提示

- **状态**：RESOLVED
- **确认路径**：用户确认工资 Excel 导入错误预览设计。
- **决定**：文件/应用错误不显示行号；单元格错误显示 Sheet1 坐标、字段、原值、原因、修改方法和稳定编号。读取错误时隐藏零统计；确认按钮禁用。
- **原因**：用户需要判断应另存文件还是修改具体单元格。
- **取舍**：底层异常只用于错误分类，不直接展示；异步结果按请求代数隔离。
- **证据**：`SalaryScreensTest` 文件级、单元格级、重新选择和失败反馈用例。

### DEC-003 — 依照 OOXML 关系解析 Sheet1

- **状态**：RESOLVED
- **确认路径**：独立审查指出合法工作簿不保证 Sheet1 文件名固定为 `sheet1.xml`。
- **决定**：从 workbook 中的 `r:id` 找到 relationship 目标，并限制到包内 `xl/worksheets/*.xml`。
- **原因**：兼容工作簿部件命名并避免外部或包外路径。
- **取舍**：拒绝外部、越界或非工作表 relationship。
- **证据**：`SalaryXlsxCodecTest.resolvesSheet1ThroughItsWorkbookRelationshipInsteadOfAssumingPartName`。

## Bug Fix 闭环

- **症状**：实机导入工资样例失败并显示“第0行”和不支持的 XML feature URI。
- **复现**：工资 → 更多 → 导入 Excel → 选择明细.xlsx。
- **根因**：强制配置 Android 不支持的 disallow-doctype-decl feature，DOM builder 创建时抛 ParserConfigurationException。
- **失败机制**：桌面 JVM Xerces 接受此 feature，掩盖平台差异；外层 catch 将 XML 整文件异常误映射成行0。
- **修复**：严格解码和声明扫描配合 Android DOM/EntityResolver；按文件、应用和单元格输出结构化可执行提示。
- **回归保护**：API26/API34真实样例导入导出、UTF-8/UTF-16、DTD/外链、关系路径、超限 XML、动态合并区域、错误定位、底栏导航、草稿恢复、事务失败和 UI 修改建议测试。
