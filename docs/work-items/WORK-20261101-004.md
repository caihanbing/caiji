## 工作概述

按用户批准的设计调整明细、账单、记账和分类管理界面，并新增两类银行通知的前台剪贴板识别与记账表单预填。正式交付为 0.2.2/code 5，schema 和备份格式不变。

## 范围与验收

### REQ-001 — 账单与记账 UI 优化

- **需求**：每日收入/支出横向显示；账单年份可浏览 1900 至当年；账单期间首列收窄、三项金额同宽；隐藏普通未选分类提示；未选分类也可点金额展开；备注紧邻数字键盘；分类排序改为空心折线尖角。
- **验收标准**：普通金额在窄屏首屏可见四列，长摘要可横向滑动；边界年份禁用且空年份零值；保存仍要求有效金额和分类；错误的分类停用提示保留。
- **实现证据**：`ui/LedgerScreens.kt`、`BillReportsScreen.kt`、`EntryEditorScreen.kt`、`CategoryManagerScreen.kt`。
- **验证证据**：API 34 `LedgerScreensTest`、`BillReportsScreenTest`、`EntryEditorScreenTest`、`CategorySettingsScreenTest`、`EverydayLedgerFlowTest`。
- **状态**：VERIFIED
- **延期依据**：不适用：未延期。
- **后续工作**：用户在实体设备核对布局。

### REQ-002 — 银行剪贴板识别与待保存预填

- **需求**：前台焦点恢复后读取最新剪贴板，识别“账户变动提醒/代发工资”和“交易成功提醒/网上快捷支付”；填写类型、金额、最近非未来日期；分类空白且不自动保存。
- **验收标准**：只从唯一“交易金额”字段取金额；无效模板不打开；相同文本持久去重；草稿或备份恢复期间暂存，不覆盖现有编辑；仅存 SHA-256 指纹。
- **实现证据**：`domain/ClipboardTransactionParser.kt`、`MainActivity.kt`、`ui/EntryEditorScreen.kt`。
- **验证证据**：`ClipboardTransactionParserTest` 和 API 34 `MainActivityClipboardTest.foregroundClipboardNotificationOpensPrefilledEntryOnlyOnce`。
- **状态**：VERIFIED
- **延期依据**：不适用：未延期。
- **后续工作**：实体设备验证 Android 版本和厂商剪贴板行为。

## 决策

### DEC-001 — UI 稿与通知预填规则

- **状态**：RESOLVED
- **确认路径**：用户在本轮批准 UI 稿及“采用上述规则”“去重并保护草稿”选项。
- **决定**：通知日期按不晚于今天的最近有效年份推断；收入类型为收入、网上快捷支付为支出；分类留空且不自动保存；待处理内容在表单实际打开时记入去重指纹。
- **原因**：保留用户最终分类和保存控制，同时避免通知被草稿/恢复流程覆盖。
- **取舍**：应用前台访问剪贴板会触发 Android 系统可见的剪贴板提示。
- **证据**：用户确认的方案、`ClipboardTransactionParserTest` 与前台仪器测试。

### DEC-002 — 年份范围与列宽

- **状态**：RESOLVED
- **确认路径**：用户批准 UI 稿。
- **决定**：年份范围为 1900 年至当年；三列金额等宽；长值允许整体横向滚动。
- **原因**：用户明确接受的账单视觉稿。
- **取舍**：超长数值仍需手势查看。
- **证据**：`BillReportsScreenTest.billYearCanBrowseEmptyYearsBackTo1900AndStopsAtCurrentYear` 与紧凑屏表格测试。

## 风险

### RSK-001 — 剪贴板误识别及草稿覆盖

- **状态**：MITIGATED
- **确认路径**：用户指定的两种模板、纯函数字段解析、持久指纹去重和草稿状态门控。
- **概率**：低。
- **影响**：错误填入交易或覆盖未保存内容。
- **缓解措施**：标题与类型须匹配、字段须唯一且金额和日期通过校验；分类留空；不自动保存；草稿及恢复期间延后。
- **验证**：解析边界单测及 API 34 前台重复读仪器测试通过。
