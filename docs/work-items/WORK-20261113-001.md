## 工作概述

根据用户实机验证和已批准的五状态高保真稿，优化记一笔金额布局及两种录入页的返回保护，重整新增收入的底部集中录入面板。目标版本 0.5.13/code28；不改数据库和金额业务规则。

## 范围与验收

### REQ-001 — 需求摘要

- **需求**：按批准设计稿重排记账与新增工资收入的输入界面，并按真实金额草稿判定返回是否确认放弃。
- **验收标准**：记账金额移至备注上方并两侧留 16dp；仅选分类且金额是有效正数时新建记账返回提示。新增收入未选项目时不显示输入面板；选中后可通过单行横滑字段条选择八项金额、输入及保存。收入页系统返回和标题返回一致：新建八项全空直接返回，任一非空弹确认；编辑按金额与初始值差异确认。无数据库/API 变化；测试、Lint、API26/API34 仪器回归及正式包/双端发布完成。
- **实现证据**：`EntryEditorScreen` 按有效分类与正金额判定新建放弃；`AmountDisplay` 调整到备注上方并内缩16dp，键盘位于备注下方。`SalaryEditor` 将字段栏、当前金额、扣款/纯收入摘要和键盘集中到底部，未选有效项目时隐藏；标题与系统返回共用金额草稿判定。
- **验证证据**：`:app:testDebugUnitTest :app:lintDebug` 通过；API34全量196项通过，最终录入/工资/主流程82项再次通过；API26按测试类分组196项通过，最终EntryEditor/SalaryScreens 69项与EverydayLedgerFlowTest 13项再次通过。正式 APK `app/build/outputs/apk/release/caiji-0.5.13-release.apk` 的package/version/code、minSdk/targetSdk、zipalign、V2签名和SHA-256已核验；证书SHA-256 `692d2387ba18f63ed43548d153af2a611384d8bffe1c603c3314df56ef006e1a`，APK SHA-256 `9d6e720c3a4b4e4587021d58514d0d1bb5c445d0edcad9071e472ab20db30959`。API34 AVD以官方0.5.12包写入 ¥3.00 账单/备注和 ¥123.45 工资记录，安装最终0.5.13包并重启后两条记录仍在。

## 决策

### DEC-001 — 按批准的录入改版稿实现

- **状态**：RESOLVED
- **确认路径**：用户在本会话批准五种录入状态高保真稿。
- **决定**：记账金额在备注上方并水平内缩16dp；收入页正文只选择收入项，底部单行横滑八字段条、当前金额、扣款/纯收入摘要和键盘；无收入项时不显示面板。收入页系统与标题返回统一，新建任一金额字段非空即确认、全空直接返回；编辑以八项金额草稿差异判定。记账新建则仅当分类已选且金额有效为正时确认，编辑继续保护修改。
- **原因**：修复实机反馈的空白浪费、误报放弃、重复汇总及键盘区域密集问题。
- **取舍**：底部横滑字段条可容纳较窄视口；不改变日期、税额、金额表达式与保存规则。
- **证据**：会话已批准的高保真设计稿与实施计划。
