## 工作概述

增加设置页手动检查更新，并在应用进程进入前台时自动检查 GitHub 最新正式 Release。高于当前版本时显示更新说明和下载入口；应用只在浏览器打开 GitHub APK 下载或 Release 页面。

## 范围与验收

### REQ-001 — 自动与手动检查 GitHub 正式版本

- **需求**：启动及后台返回前台时自动检查；设置页提供手动检查；只接受 `caihanbing/caiji` 最新正式 Release。
- **验收标准**：按数值比较 `vMAJOR.MINOR.PATCH`；并发请求合并；自动无更新/失败不打断记账；手动检查反馈最新/失败；取消自动更新提示后，本进程抑制同一版本且手动检查仍可提示。
- **实现证据**：`GitHubReleaseSource`、`ReleaseVersion`、`UpdateManager`、`CaijiApplication.onStart` 和设置页 `SettingsScreen`。
- **验证证据**：`:app:testDebugUnitTest`、`:app:lintDebug`、`:app:assembleRelease` 通过；API26 全量 126 项、API34 最终全量 127 项仪器回归通过，最后实现调整后两台模拟器各 7 项更新测试通过。
- **状态**：VERIFIED
- **延期依据**：不适用：未延期。
- **后续工作**：不适用：未延期。

## 决策

### DEC-001 — 浏览器下载最新正式 Release APK

- **状态**：RESOLVED
- **确认路径**：用户批准的实现计划和设置更新高保真稿。
- **决定**：使用 GitHub 最新正式 Release；若存在对应 APK 附件则打开该下载链接，否则打开 Release 页面。
- **原因**：继续使用仓库当前正式 APK 发布渠道并保持更新操作由用户显式启动。
- **取舍**：应用不内置下载器或安装权限流程。
- **证据**：`docs/release/macOS-install.md` 与用户确认。

## 风险

### RSK-001 — 网络检查不能干扰本机记账

- **状态**：MITIGATED
- **确认路径**：Work Item 验证结果。
- **概率**：中。
- **影响**：GitHub 无法访问时错误提示遮挡记账或前台切换触发重复网络请求。
- **缓解措施**：10 秒连接/读取超时，自动错误静默，合并在途请求，链接固定 HTTPS GitHub 主机。
- **验证**：请求协调和管理器 JVM 测试，API26/API34 设置与 Release 解析仪器测试。
