## 工作概述

依据用户认可的高保真稿，统一收入项与分类管理列表和编辑交互，按当前分页类型创建项目，并将更新检查改为 Gitee 优先、失败回退 GitHub。发布版本 0.5.11/code26；同一签名 APK、SHA-256 sidecar 及代码同步至 GitHub 和 Gitee。

## 范围与验收

### REQ-001 — 管理体验、更新源与双平台交付

- **需求**：收入项管理采用现金/非现金分页且仅显示对应性质；分类管理与收入项管理列表及弹窗对齐。新增项目类型由已停稳的当前页决定，编辑固定现有类型。同性质内排序、停用保留历史。手动和自动更新均先查询 Gitee；网络/HTTP/解析/发布数据校验失败才查询 GitHub；有效旧版本是成功结果，取消不触发回退。
- **验收标准**：收入项现金/非现金切页同步，新增/编辑收入项和分类无需在弹窗选择类型，类型正确且失败后草稿保留；排序只调整同性质，排序失败回滚且边界箭头禁用；设置显示 Gitee 优先说明。Gitee 返回有效新版本后提示新版本、有效当前版本显示最新；Gitee 失败使用 GitHub 结果；两端失败时手动显示失败、自动静默。API26/API34 全量仪器测试通过；0.5.11 正式签名包覆盖安装保留账本、工资及项目目录；两端 Release 下载附件哈希一致。
- **实现证据**：`SalaryTypesScreen`、`CategoryManagerScreen`、`RoomSalaryRepository.moveIncomeType`、`ReleaseSource` / `OrderedReleaseSource`、`GiteeReleaseSource` 和 `GitHubReleaseSource`。
- **验证证据**：API26/API34 全量仪器测试各 186 项通过；JVM 单测和 Lint 通过；正式签名 APK 身份及 SHA-256 校验通过；API34 模拟器 0.5.10→0.5.11 覆盖升级保留 ¥3.00 账单、¥100.00 工资及原收入项目录；GitHub/Gitee main、标签及两个 Release 资产已核验。

## 决策

### DEC-001 — 已确认的交互及来源规则

- **状态**：RESOLVED
- **确认路径**：用户批准本会话高保真稿及实施计划。
- **决定**：以分类管理样式统一两个管理页；当前分页固定新增类型；收入项仅在相同现金性质内移动；手动与自动检查均按 Gitee→GitHub 顺序，只有 Gitee 查询失败才回退。
- **原因**：消除同类管理交互差异，并适配 Gitee 在用户环境中的更新可达性。
- **取舍**：有效但不是较新版本的 Gitee Release 直接结束检查，不探测 GitHub 是否存在更新。
- **证据**：已批准高保真稿、用户对排序范围及检查入口范围的选择、对 Gitee 最新 Release API 的只读请求验证。

## 风险

### RSK-001 — 排序和跨平台更新风险

- **状态**：CLOSED
- **确认路径**：Room Repository 事务测试、来源回退单测、API26/API34 仪器回归及发布附件核验。
- **概率**：低：性质分页和来源标签均有回归覆盖。
- **影响**：高：排序损坏会影响现存项目，错误 Release 链接会中断更新安装。
