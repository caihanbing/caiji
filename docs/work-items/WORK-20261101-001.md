### DEC-004 — macOS Gradle 并发

- **状态**：RESOLVED
- **确认路径**：2026-11-01 通过读取 Gradle/代理状态并以二 worker 重跑 testDebugUnitTest 验证。
- **决定**：在 macOS release build 脚本及本工作项的本机 Gradle 验证命令上限为 2 workers；不改系统代理或全局 Gradle 并发设置。
- **原因**：默认 12 workers 下 Maven Central 依赖经本机代理时出现 TLS handshake failure；同一代理的 curl 连接成功，Gradle 降为 2 workers 后单测通过。
- **取舍**：本机 Gradle 构建可能较慢，但避免改变其他项目共享的网络/并发设置。
- **证据**：Maven Central direct/proxy curl 对目标 JAR 均返回 200；Gradle daemon 的系统代理为 127.0.0.1:7897，默认 12 leases；testDebugUnitTest --max-workers=2 通过。

## 风险

### RSK-001 — 新签名不兼容覆盖安装

- **状态**：MITIGATED
- **确认路径**：APK 签名与安装流程验证。
- **概率**：确定：同一 applicationId 使用不同证书不能覆盖旧版。
- **影响**：直接尝试覆盖会失败；卸载而未备份会丢失仅存于应用数据库的账单。
- **缓解措施**：交付指南明确先导出并验证加密备份，再卸载旧 APK，安装新版后恢复；不在用户设备上自动执行卸载。
- **验证**：final APK package/version/minSdk、签名、alignment 和 SHA-256 已核验；API34 AVD fresh install + 格式2 restore 成功。AVD 拒绝 debug 签名包覆盖 release (`INSTALL_FAILED_UPDATE_INCOMPATIBLE`)。旧 0.1.0 APK 不在当前仓库，因此实际旧证书未直接比对。

### RSK-002 — Android SDK Agreement 与 API 34 环境配置

- **状态**：MITIGATED
- **确认路径**：用户于 2026-11-01 回复“已接受 Google Android SDK License Agreement”；随后使用官方 Android CLI 安装 API 34/build-tools/emulator。
- **概率**：中；当前未安装 Android SDK，首次装包可能显示 Google SDK license。
- **影响**：未安装平台和模拟器则 Gradle 构建和设备回归无法完整执行。
- **缓解措施**：用户于 2026-11-01 明确回复“已接受”；使用官方 Android CLI 并关闭 metrics，安装最小 API 34 ARM64 package set。
- **验证**：platforms/android-34、build-tools/34.0.0、platform-tools、emulator、system-images/android-34/google_apis/arm64-v8a 已安装；AVD Caiji_API_34 可启动并报告 API 34。

### RSK-003 — Maven Central TLS 受本机代理并发影响

- **状态**：MITIGATED
- **确认路径**：2026-11-01 检查本机 127.0.0.1:7897 代理和 Maven Central 连通性后，以 Gradle max-workers=2 重试。
- **概率**：中；本机系统代理偶发地终止大量并行 TLS 请求。
- **影响**：依赖解析阶段可能令测试或正式构建失败。
- **缓解措施**：仅本机 macOS 构建脚本和验证命令限为 2 workers，不调整系统代理或所有项目通用配置。
- **验证**：testDebugUnitTest、lintDebug、assembleRelease 在 max-workers=2 下通过；基线签名 APK 已生成并完成 apksigner/SHA-256 核验。
