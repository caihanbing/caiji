## 决策

### DEC-001 — 成功提示复用现有成功状态

- **状态**：RESOLVED
- **确认路径**：用户已确认基于实机截图制作的高保真成功提示稿。
- **决定**：工资导出成功文案归类为 SUCCESS，复用现有绿色成功提示条；取消和写入失败保持原语义。
- **原因**：当前成功文案未命中成功白名单，落入默认 ERROR。
- **取舍**：保留页面布局和关闭操作，只纠正提示语义和颜色。
- **证据**：用户批准的高保真稿及提示分类回归测试。

### DEC-002 — 逐列减法计算非现金合计

- **状态**：RESOLVED
- **确认路径**：用户选择以业务数据一致为验收标准；比较原样例与实机导出文件。
- **决定**：C:K 每列非现金合计等于该列全部收入合计减同列现金收入合计，并保留相符的缓存值。
- **原因**：当前公式误用 C 列并引用自身行；缓存结果掩盖了 Excel/WPS 重算错误。
- **取舍**：同日顺序、空金额显示零、两条特殊边框差异不属于本次标准。
- **证据**：原样例与导出逐笔多重集相同；检查到 `K184` 为 `C184-C183`。

## Bug Fix 闭环

- **症状**：全部导出成功后仍显示“出错”；电子表格重算非现金合计可能循环引用。
- **复现**：工资 → 更多 → 导出 Excel → 全部记录 → 保存；检查导出页提示与三类合计最后一行公式。
- **根因**：工资成功文案未加入成功文案映射；非现金公式分支对所有列复用了 `C` 并引用当前非现金行。
- **失败机制**：未知成功消息默认归为 ERROR；缓存汇总掩盖了公式重算时的错误依赖。
- **修复**：将工资导出成功分类为 SUCCESS；逐列生成“总计行减现金行”公式和对应缓存结果。
- **回归保护**：成功/取消/写入失败提示用例；C:K 每列公式与缓存断言；API26/API34 样例导入/导出/重导入及电子表格重算。
