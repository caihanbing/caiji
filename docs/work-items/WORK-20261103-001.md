## 工作概述

修复 0.3.1 实机回归中的分类管理开关迟缓、账单横滑距离偏长、报告排行榜加载迟缓及汇总闪动。沿用已批准的界面稿与交互规则，发布正式签名 0.3.2/versionCode 9。

## 范围与验收

### REQ-001 — 分类管理切页状态

- **需求**：Pager 两页的分类开关从页面出现时就按真实启停状态显示；滑动过程中不执行启停、编辑和排序。
- **验收标准**：未激活页开关不因页状态变灰；停稳后当前页操作有效；排序期间原操作锁与失败回滚保持。
- **实现证据**：`CategoryManagerScreen` 按页使用 `Category.active` 呈现开关；操作回调检查 Pager 已停稳且位于当前页。
- **验证证据**：API34 `CategorySettingsScreenTest.categoryTypeSelectionTracksSwipeBeforeThePageSettles` 检查中途目标开关语义为 enabled；`categoryArrowMoveLocksDuringSaveAndFailurePreservesOrder` 检查排序期间保护。
- **状态**：VERIFIED
- **延期依据**：不适用：未延期。
- **后续工作**：用户实机确认开关视觉响应。

### REQ-002 — 账单横滑响应和横滚接力

- **需求**：账单月/年 Pager 与其他 Pager 使用相同切页阈值；未溢出的金额/表格让 Pager 接收滑动；溢出时表格先横滚并在边界交接剩余拖动/惯性。
- **验收标准**：相同快速手势在汇总卡与短表行可以切页；超宽金额先横滚，滚到左右边界后可切页；表头与数据同步，纵向滚动及行点击正常。
- **实现证据**：`PeriodSummaryCard` 与 `BillPeriodTable` 仅在横向内容溢出时启用 `horizontalScroll`，避免无可滚动距离时拦截 Pager。
- **验证证据**：API34 `summaryCardSwipeBeyondThePagerThresholdPassesThroughItsNonOverflowingAmounts`、`shortBillRowPassesHorizontalSwipeToMonthYearPager` 和 `compactBillTableScrollsAsOneAndKeepsRowsClickable`；38% 低速拖动在账单和分类 Pager 均未越过共用默认阈值，故保留批准计划指定的相同阈值。
- **状态**：VERIFIED
- **延期依据**：不适用：未延期。
- **后续工作**：用户实机核对自然手势速度与距离。

### REQ-003 — 报告排行快照和汇总稳定

## 决策

### DEC-001 — Pager 阈值

- **状态**：RESOLVED
- **确认路径**：用户批准的 0.3.2 实施计划明确要求账单 Pager 使用与其他页面相同的切页阈值。
- **决定**：保留 Compose Pager 共用默认阈值，不单独降低账单阈值；仅关闭未溢出内容的横滚手势处理。
- **原因**：保持各页面切页手感一致，修复无实际横滚距离时子节点拦截手势的问题。
- **取舍**：慢拖未跨过默认位置阈值时仍停留原页；快速甩动与各页面一致。
- **证据**：相同 38% 低速拖动对分类 Pager 和账单 Pager 均不切页；超过阈值的账单摘要测试通过。

### DEC-002 — 报告缓存范围

- **状态**：RESOLVED
- **确认路径**：用户批准的计划要求一次加载期间汇总与收/支双排行，并在修改账单/分类或恢复账本后失效。
- **决定**：缓存只保存在当前 `LedgerViewModel` 内存；不持久化、不改变 Room 或备份格式；结果按起止日期校验。
- **原因**：降低类型切换的数据库等待，同时阻止旧期间结果串显。
- **取舍**：离开并重建 ViewModel 后会重新查询；同期间返回且数据未变时复用内存快照。
- **证据**：快照期间范围字段、独立请求门闩及期间不匹配仪器测试。

## 风险

### RSK-001 — 横向表格与 Pager 手势竞争

- **状态**：MITIGATED
- **确认路径**：API34 汇总卡、短表、超宽表格起点及左右边界回归。
- **概率**：中。
- **影响**：误切月/年或表格无法横滚。
- **缓解措施**：非溢出时关闭子滚动；溢出继续使用 Compose 嵌套横滚；保留父 Pager 边界接力测试。
- **验证**：REQ-002 所列仪器测试通过。

### RSK-002 — 期间快照与账单写入并发

- **状态**：MITIGATED
- **确认路径**：检查 `LedgerViewModel.refresh`、恢复入口、完整日期范围请求键和期间查询门闩。
- **概率**：低。
- **影响**：旧汇总或排行在账单修改后重新显示。
- **缓解措施**：写入成功/恢复完成的刷新同步使门闩失效并清除快照；所有结果校验请求序号和日期范围。
- **验证**：期间隔离仪器测试、Room 同事务双排行读取和全量回归。

### RSK-003 — 返回缓存期间与其他在途查询竞争

- **状态**：MITIGATED
- **确认路径**：独立审查发现 A→B 慢查询→返回缓存 A 时，B 可能覆盖快照并把 B 的错误显示在 A。
- **概率**：低。
- **影响**：页面因期间校验隐藏 B 后，A 可能没有排行、加载状态或错误反馈。
- **缓解措施**：请求键使用完整日期范围；命中 A 缓存时撤销不同期间的活动请求，清除加载与错误；结果仍须匹配当前门闩。
- **验证**：`PeriodRankingRequestGateTest` 覆盖缓存 A 撤销慢查询 B、同期间请求保留及年度/一月键不同。

## Bug Fix 闭环

- **症状**：分类管理左右滑动中停用开关变灰迟缓；账单页比其他页面更难滑动切页；报告切换收入/支出时排行榜慢加载且汇总卡闪动。
- **复现**：API34 `CategorySettingsScreenTest.categoryTypeSelectionTracksSwipeBeforeThePageSettles` 初始断言失败；账单汇总卡快速横滑通过区域性仪器输入验证；报告类型切换的现有 `LaunchedEffect` 将类型变化作为数据库查询键。
- **根因**：分类开关的 `enabled` 同时承担切页保护和状态呈现；汇总金额和表格在未溢出时仍安装横向滚动输入处理；报告在类型停靠时查询单类数据并清空共享报告状态，导致两类排行串行显示且 summary 重组。
- **失败机制**：非活动 Pager 页的 Switch 语义报告 disabled；没有滚动距离的子级仍参与横向手势；报告刷新在切页后才开始且 `periodReport` 先置空。
- **修复**：各页开关照常展示真实数据，只有动作回调在滑动中拦截；非溢出区域不启用横滚；同一 Room 只读事务返回两类排行及汇总，类型变化仅选择已加载 Pager 页。
- **回归保护**：新增期间双榜聚合和 Room 测试、Pager 中途开关状态、汇总卡快速横滑、目标排行拖动中可见与期间不串显测试。
- **决定**：不单独降低账单 Pager 的切页阈值。
- **原因**：计划要求与其他页面共用阈值；API34 对比测量同样的 38% 低速拖动未跨过两处 Pager 的默认阈值。
- **取舍**：低速不足阈值的滑动仍返回原页，超阈值与甩动按共用 Pager 规则处理。
- **证据**：`CategorySettingsScreenTest` 与 `BillReportsScreenTest.summaryCardSwipeBeyondThePagerThresholdPassesThroughItsNonOverflowingAmounts`。
