## 工作概述

为工资记录增加可管理的扣款目录及收入/扣款默认金额，完善两类明细排序，并识别无卡支付剪贴板通知。保持历史工资、旧 Excel 和既有记账流程兼容，交付 0.5.17 正式 APK。

## 范围与验收

### REQ-001 — 需求摘要

- **需求**：新增扣款项管理，工资收入项和扣款项均支持默认金额。收入项明细与分类明细可切换金额和时间排序，使用无卡支付通知自动预填支出。
- **验收标准**：Room 3→4 保留历史记录；自定义扣款进入工资净额、重复校验、Excel 导入导出和目录恢复；金额以分保存，默认值首次选用时填入，已编辑金额保留；分类明细金额降序为默认，收入项明细时间降序为默认；剪贴板样例预填支出 ¥35.20 和 11 月 21 日且不自动保存。
- **实现证据**：`SalaryDatabase` / `RoomSalaryRepository` / `SalaryXlsxCodec`、`SalaryScreens`、`BillPeriodReportScreen`、`ClipboardTransactionParser`。
- **验证证据**：JVM全量、Lint、Release构建、API34全量206项、API26全量204/206及两项单独重跑、工资/目录/排序/XLSX定向仪器测试均有通过证据。正式APK签名、版本和摘要已核验；GitHub/Gitee Release 两个附件均已下载并与本地文件逐字节核验，用户安装后的回归待完成。

## 决策

### DEC-001 — 扣款目录与旧记录映射

- **状态**：RESOLVED
- **确认路径**：用户已确认
- **决定**：现有七种扣款保留在同一扣款目录中，以稳定 ID 对应原工资列；自定义扣款逐笔按 ID 关联，收入与扣款目录的默认值和状态随 XLSX 元数据保存。
- **原因**：既有工资表使用七个固定扣款字段，保持列和历史计算兼容。
- **取舍**：扣款目录与收入项目录分开，旧固定列继续用于七种内置扣款。
- **证据**：用户在设计确认阶段选择共用扣款目录和完整 Excel 迁移。
