## 工作概述

依据已批准的三屏稿，将新增和编辑收入重做为记账风格的现金／非现金切换、收入项网格、金额键盘和可折叠扣款。新增默认现金且不预选项目；切换保留金额日期与扣款、清空项目。发布 0.5.10/code25，同步 GitHub 与 Gitee 的代码和发行附件。

## 范围与验收

### REQ-001 — 需求摘要

- **需求**：新增/编辑工资录入复用“记一笔”交互样式，并仅显示所选现金性质的启用收入项；切换性质保留其他草稿而清除项目。所有工资金额通过应用内键盘输入，支持扣款逐项编辑与负税。
- **验收标准**：新增现金页无预选项目；合法选项选中后可保存；无选择、无启用类型、未来日期、负纯收入、无效表达式、精度超限和溢出不可保存。切换不丢金额扣款日期；历史停用项目可编辑；账单键盘行为无回归；0.5.10 APK 同签名升级保留本地数据；双平台 main/tag/release 附件内容一致。
- **实现证据**：`SalaryEditor` 与 `AmountKeypad` 使用现金性质筛选网格、字段目标输入、签名税值切换及固定自绘键盘；`SalaryAmountInput` 独立处理工资整数分和表达式；`EntryEditorScreen` 复用键盘并保持账单求值。
- **验证**：JVM、Lint、API26/API34 仪器全量回归均通过（各 182 项）。测试覆盖现金/非现金页签同步、日期及八个金额字段切换保留、非现金新增/编辑草稿导航恢复和同签名覆盖升级。
- **验证证据**：正式包身份/签名/哈希、覆盖升级及双端发行核验见 VER-002。
- **状态**：VERIFIED

## 决策

### DEC-001 — 收入录入交互与切换语义

- **状态**：RESOLVED
- **确认路径**：用户已批准会话高保真稿和实施计划。
- **决定**：采用记账式分段按钮、金额区、四列收入项网格及自绘键盘；新增现金页手动选收入项；现金性质切换时保留其他金额草稿并清空选择。
- **原因**：用户实机确认新增收入和记一笔样式/交互差异过大。
- **取舍**：无选择时需显式选择收入项后才能保存。
- **证据**：`docs/superpowers/specs/2026-11-11-salary-editor-unification-design.md` 及本会话获批三屏高保真稿。
