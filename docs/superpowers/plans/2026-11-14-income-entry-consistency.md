# 收入录入与界面统一实施计划

**目标：** 按已批准设计稿完善收入录入管理入口和金额区顺序，并核对全应用相似控件的一致性。

**方案：** 复用 Compose 已有分类管理入口、收入项管理路由、AmountDisplay、AmountKeypad 与青竹主题。将收入字段控件与账单备注统一为 56dp 最小行高；仅在审查发现确切的同角色样式漂移时调整对应 UI。

**技术栈：** Kotlin、Jetpack Compose、Material 3、现有 Android Instrumentation、Gradle Release APK。

**设计稿：** `/Users/caihanbing/.codex/visualizations/2026/11/14/01a1d8dd-d3e3-7d32-b798-47d96cf11b97/caiji-income-entry-review.png`（用户已确认）

## 约束

- 用户批准的稿件限定本轮界面变化；实质性视觉偏差须再次确认。
- 保留五套现有主题、既有数据行为及管理页中的停用历史项目规则。
- 在当前 `main` 工作区完成，保留原有未提交文档修改，不创建分支或新工作区。
- 完成后构建、核验并发布版本化 APK 至 GitHub 与 Gitee。

## 实施步骤

1. 把收入页“选择收入项”标题行替换为与分类编辑器一致的标题及右侧管理按钮；将现有收入项管理返回路线指向编辑器，并把当前输入字段状态提升到路由存活层。
2. 调整输入 dock 次序为纯收入/扣款合计摘要、金额显示、字段选择行、数字键盘。字段行高度 56dp，金额仍复用共享组件；税正负按钮保留在字段行右侧。
3. 审核所有功能页共享控件及同类控件的尺寸、字号、间距、圆角、图标、主题色、禁用和错误状态，只修正可证实的差异并保留页面特有行为。
4. 完成收入编辑往返、不同输入字段与现金分页、空列表和长文案检查；更新 Feature Docs 与 Work Item 的实现/验证证据。
5. 生成并核验 Release APK、签名、版本及 SHA-256；提交并直推两个 main，创建同版本双 Release，下载核对附件。

## 验收

- 收入项管理按钮位置、图标和字号与“管理分类”一致；返回后草稿、分页及当前输入字段可恢复。
- 收入/扣款字段行在备注下方、金额上方，字段按钮最小行高为 56dp；摘要顺序为纯收入在前、扣款合计在后。
- 同类控件在五个主题中一致，并在 320dp 与大字号下可见、可操作、无不合理溢出。
- Android 测试、Lint、Release 构建与包身份/签名/校验和检查通过；双端 Release 附件一致。
