# 财记 V0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Build and deliver the Chinese offline personal ledger as a signed Android 8+ APK.

**Architecture:** Single-activity Jetpack Compose UI with ViewModels, repositories, and Room. Store money as integer fen, dates as local calendar days, and references by stable category IDs. Create and validate authenticated, versioned AES-GCM backup files before transactionally replacing the database.

**Tech Stack:** Kotlin, Android Gradle Plugin, Jetpack Compose Material 3, Room, Android document picker, Java Cryptography APIs, JUnit, Android instrumentation tests.

**Spec:** `docs/superpowers/specs/2026-10-31-caiji-design.md`

## Global Constraints

- Minimum Android API 26; use a Chinese light yellow theme.
- No accounts, network permission, advertisements, analytics, or Android cloud backup of ledger data.
- Ledger amounts are positive integral fen; reject future dates and entries without an active category.
- A used inactive category stays linked to historical entries.
- Backup encryption uses AES-GCM and a fresh random salt and nonce per file; never store backup passwords.
- Restore must validate first, make a user-selected encrypted backup before replacing non-empty data, and preserve existing data on failure.
- Keep the release signing key and credentials outside Git and reuse that key for upgrade builds.
- Do not commit changes.

## Review Focus

- Tampered ciphertext, invalid GCM tags, and malformed backup fields never write to or erase the existing database.
- Interrupted full restore rolls back all tables and preserves category-to-entry references.
- Integer-fen calculations do not round unexpectedly or wrap on overflow.
- Local dates display and aggregate correctly across month and year boundaries regardless of UTC offset.
- Inactive category history survives editing, restart, backup, and restore.
