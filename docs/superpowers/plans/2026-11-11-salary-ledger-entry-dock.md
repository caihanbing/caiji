# 财记录入页统一与键盘交互优化实施计划

> **实施要求：** 按 TDD 顺序执行，每个改动先补回归断言；当前工作区与 `main` 保持一致，不创建分支。

**目标：** 对齐新增工资收入和“记一笔”的输入网格，并将金额显示移入随自绘键盘展开的底部输入区。

**架构：** 在 `AmountKeypad.kt` 增加共享金额显示组件；账单页仅在输入区展开且系统输入法隐藏时显示金额与应用内键盘。工资页复用该组件，收入项网格改为记账页密度，新建仅在选择有效收入项后展开，编辑默认展开。保留两类记录各自的求值和保存校验。

**技术栈：** Kotlin、Jetpack Compose、Compose 仪器测试、Room 既有仓库。

**设计依据：** `docs/superpowers/specs/2026-11-11-salary-editor-unification-design.md` 与用户批准的 A–D 高保真效果图。

## 全局约束

- 用户可见界面必须遵循已批准的 A–D 效果图。
- 现金性质切换清空收入项、保留日期和八项金额，并收起键盘。
- 工资金额空值按零、税可为负、纯收入不得为负；账单只接受正金额。
- 不变更数据库、备份或 XLSX 数据格式；不泄露正式签名密钥。
- 发布版本为 0.5.12、versionCode 27；在当前 `main` 完成并同步 GitHub/Gitee。

## 重点回归

- 新增工资无项目：不显示金额键盘；触碰金额行不能打开；选择收入项后金额区和键盘出现。
- 切换现金性质后键盘及日期键隐藏，八项草稿保留；重新选项目后金额和日期恢复。
- 工资键盘显示当前字段金额；负税和无效表达式遵守现有校验。
- 编辑工资和账单初入展开；新账单选择分类前不显示金额；剪贴板预填继续展开。
- 备注系统输入法隐藏金额和应用内键盘，IME 完成后恢复；失败保存保留草稿。

## 实施步骤

1. 更新工资和账单 Compose 仪器测试，固定初入、选择/切换、编辑、字段显示与恢复行为。
2. 在 `AmountKeypad.kt` 实现可带标签、金额与错误信息的共享金额区。
3. 在 `EntryEditorScreen.kt` 将金额移到底部输入区，并保持备注 IME 互斥。
4. 在 `SalaryScreens.kt` 对齐收入项网格，按项目选择状态控制底部区，金额跟随当前字段，保留税符号按钮。
5. 运行 API26/API34 仪器回归、JVM 与 Lint；处理失败后重跑受影响检查。
6. 完成代码审查，更新 `salary-records`、`ledger-entries` 档案和 Work Item，执行 fresh 验证。
7. 更新应用版本，构建并验证签名 APK 与 SHA-256；同签名覆盖升级后提交并推送两个 `main`，创建并验证匹配 Release 附件。
